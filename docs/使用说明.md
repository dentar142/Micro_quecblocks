# UniKnect EC200U 积木工作台使用说明

> 当前入口以 `builder/easy_api_main_builder_microblocks.html` 为准。本文后半部分保留的 `UniversalKit` 命令是高级诊断流程，不是积木工作台的主入口。

## 当前推荐流程

1. 上传一次 `runtime/starter/` 的完整运行库，保留 `easy_api_parts/` 和 `lib/` 目录结构。Windows 的 COM 号以设备管理器当前枚举结果为准，不要照抄旧文档中的 COM17。
2. 打开 `builder/easy_api_main_builder_microblocks.html`。这是当前唯一的积木、LCD 画布、模板、代码生成、复制和下载入口。
3. 在左侧选择积木：模块启用放“启动区”；按键、GPIO、UART/BLE 接收放“快速轮询框”；传感器、LCD、SD、音频和定位刷新放“慢速刷新框”。
4. USER 蓝色按键在条件积木中选择“USER 按键”，生成事件名 `user`；LCD Shield 五向键选择上、下、左、右或中间/确认，二者不是同一个输入。
5. 点击“复制 main.py”或“下载 main.py”，再在 Thonny 选择 MicroPython (generic) 和当前开发板端口上传导出的 `main.py`。

界面允许在有语法/配置诊断时继续复制或下载；先查看诊断面板中的具体行号，再决定是否烧录。

这份文档用于比赛现场快速使用通用代码包。目标是：不针对每道题临时重写代码，只修改配置，然后用统一命令验证 GPIO、定时器、PWM、I2C、SPI、ADC、UART、按键、LED、LCD、传感器、存储和音频等考点。

## 1. 你需要准备什么

- 开发板：UniKnect / NUCLEO-F413ZH 相关套件。
- 串口：波特率 `115200`；Windows COM 号以当前设备管理器枚举结果为准。
- 软件：Python、pyserial、Thonny 或本包提供的 REPL 烧录脚本。
- 文件夹：使用 `runtime/starter/` 作为上传到板子的代码目录。
- 杜邦线：GPIO、PWM、UART、SPI、RS485 等回环测试需要按题目接线。

## 2. 最快使用方式：自动烧录并验证

在仓库根目录 `uniknect-micropython` 下运行：

```powershell
python -B .\tools\repl_flash_verify.py --port COM19
```

脚本会自动完成：

1. 进入 MicroPython raw REPL。
2. 上传 `runtime/starter/` 下的完整运行库。
3. 运行默认安全验证项目。
4. 输出 `PASS / FAIL / SKIP` 结果。

默认验证通过时会看到类似结果：

```text
[FLASH][PASS] files=16
[TEST][PREFLIGHT][PASS]
[TEST][LED][PASS]
[TEST][ADC][PASS]
[TEST][I2C][PASS]
[TEST][SENSORS][PASS]
[TEST][TIMER][PASS]
[TEST][SPI_LCD][PASS]
[TEST][STORAGE][PASS]
[SUMMARY] PASS=8 FAIL=0 SKIP=0
```

如果脚本提示串口占用，请先关闭 Thonny 的串口连接，再重新运行。

## 3. 手动使用方式：Thonny 上传

如果不用自动脚本，可以用 Thonny：

1. 打开 Thonny。
2. 选择 MicroPython 解释器和当前枚举的 ST-LINK COM 口。
3. 把 `runtime/starter/` 整个目录上传到开发板根目录。
4. 运行板子上的 `main.py`。
5. 看到 `kit>` 后输入命令。

## 4. 运行命令

板子启动后会进入通用命令界面：

```text
kit>
```

直接输入命令并回车：

```text
preflight
adc
i2c
sensors
uart
storage
all
```

也可以在 Thonny REPL 中手动调用：

```python
from universal_main import UniversalKit

app = UniversalKit()
app.help()
app.run("adc")
app.run("i2c")
app.run_all()
```

如果使用零基础函数封装，可以这样写：

```python
from easy_api import *

init()
guangmin(1)
i = readguangmin()
print(i)

anjian(1)
event = waitanjian()
print(event)
```

## 5. 常用命令说明

| 命令 | 用途 | 是否需要额外接线 |
|---|---|---|
| `preflight` | 检查固件内置模块是否齐全 | 否 |
| `led` | 轮流点亮板载 LED | 否 |
| `button_led` | 按键触发 LED 翻转 | 否 |
| `adc` | 读取光敏电阻 ADC | 否 |
| `i2c` | 扫描 I2C 地址 | 否 |
| `sensors` | 读取温湿度和加速度传感器 | 否 |
| `timer` | 验证定时器周期回调 | 否 |
| `spi_lcd` | 验证 SPI LCD 显示 | 否 |
| `storage` | 验证存储读写 | 否 |
| `gpio` | GPIO 输出输入回环 | 是 |
| `pwm` | PWM 输出并测频率/占空比 | 是 |
| `spi_loopback` | SPI MOSI/MISO 回环 | 是 |
| `uart` | UART TX/RX 回环 | 是 |
| `rs232` | RS232 模块回环 | 是，必须接 RS232 转换器 |
| `rs485` | RS485 模块回环 | 是 |
| `buzzer` | 蜂鸣器测试 | 视硬件而定 |
| `audio` | 麦克风录音、扬声器播放/TTS | 视硬件而定 |
| `hmi` | LCD + 五向键菜单 | 否 |
| `all` | 运行全部通用项目 | 部分项目会因未配置而 SKIP |

## 6. 修改配置

所有现场配置都集中在：

```text
runtime/starter/config.py
```

常见修改示例：

### GPIO 回环题

题目要求一个 GPIO 输出、一个 GPIO 输入时，用杜邦线短接两个引脚，然后配置：

```python
GPIO_LOOP_OUT_PIN = "D2"
GPIO_LOOP_IN_PIN = "D3"
```

运行：

```text
gpio
```

### PWM 题

PWM 需要一个输出脚和一个测量脚。用杜邦线把输出脚接到测量脚：

```python
PWM_OUTPUT_PIN = "D5"
PWM_MEASURE_PIN = "D6"
PWM_TIMER_ID = 3
PWM_TIMER_CHANNEL = 1
```

运行：

```text
pwm
```

通过条件默认是约 `1 kHz`、`50%` 占空比。

### UART 回环题

把 UART TX 和 RX 用杜邦线短接，确认串口号：

```python
UART_ID = 2
UART_BAUDRATE = 115200
```

运行：

```text
uart
```

### SPI 回环题

把 MOSI 接 MISO，并打开功能开关：

```python
FEATURES["spi_loopback"] = True
SPI_ID = 1
SPI_LOOPBACK_BAUDRATE = 1000000
```

运行：

```text
spi_loopback
```

### RS232 题

RS232 不能直接用 STM32 GPIO 电平连接，必须使用 RS232 电平转换模块。确认接好转换器后再打开：

```python
FEATURES["rs232"] = True
RS232_TRANSCEIVER_CONFIRMED = True
```

运行：

```text
rs232
```

### RS485 题

确认 A/B 线、收发方向控制脚，并配置：

```python
FEATURES["rs485"] = True
RS485_DIRECTION_PIN = "D7"
```

运行：

```text
rs485
```

### 蜂鸣器或音频题

默认关闭，确认硬件和引脚后再打开：

```python
FEATURES["buzzer"] = True
BUZZER_PIN = "D8"
BUZZER_ACTIVE = True

FEATURES["audio"] = True
```

运行：

```text
buzzer
audio
```

## 7. 如何看结果

每个测试都会输出固定格式：

```text
[TEST][项目名][PASS] 说明
[TEST][项目名][FAIL] 错误原因
[TEST][项目名][SKIP] 跳过原因
[SUMMARY] PASS=数量 FAIL=数量 SKIP=数量
```

含义：

- `PASS`：代码运行并验证成功。
- `FAIL`：代码已运行，但硬件、接线、固件或配置不满足要求。
- `SKIP`：该功能未开启，或缺少必要引脚配置。

现场优先处理顺序：

1. `FAIL`：检查接线、供电、串口号、外设地址。
2. `SKIP`：检查 `config.py` 的功能开关和引脚。
3. `PASS`：记录结果，不要再改相关代码。

## 8. 推荐比赛流程

1. 上电，确认 COM 口。
2. 自动烧录：

   ```powershell
   python -B .\competition-offline-kit\tools\repl_flash_verify.py --port COM17
   ```

3. 运行：

   ```text
   preflight
   ```

4. 不确定题目时运行：

   ```text
   all
   ```

5. 根据题目接线，修改 `config.py`。
6. 重新烧录或用 Thonny 上传修改后的 `config.py`。
7. 运行对应命令，例如 `gpio`、`pwm`、`uart`。

## 9. 常见问题

### 串口打不开

- 关闭 Thonny、串口助手或其他占用 `COM17` 的程序。
- 拔插 USB 后重新确认 COM 口。

### 运行后没有 kit> 提示

按 Ctrl+C 中断，再输入：

```python
import main
```

或重新软复位开发板。

### GPIO/PWM/UART 一直 FAIL

优先检查杜邦线是否接对。回环类测试必须真实短接：

- GPIO：输出脚接输入脚。
- PWM：输出脚接测量脚。
- UART：TX 接 RX。
- SPI：MOSI 接 MISO。

### I2C 没有地址

检查传感器供电、SDA/SCL 是否接反，或者运行：

```text
i2c
```

正常板载传感器通常能看到 `0x38` 和 `0x19`。

### RS232 不能通过

确认不是 TTL 直连。RS232 需要电平转换模块，否则不要开启 `RS232_TRANSCEIVER_CONFIRMED`。

## 10. 最重要的原则

- 只改 `config.py`，不要临场改底层库。
- 有杜邦线的题，先画清楚“哪个脚接哪个脚”再运行。
- 先跑 `preflight`，再跑单项命令。
- 遇到 `SKIP` 先补配置，遇到 `FAIL` 先查接线。
- 比赛现场优先保证能稳定演示，不追求把所有默认关闭项目都打开。


## LCD 行列显示、串口选择和 main.py 轮询

LCD 可以显示文字，也可以显示变量：

```python
showlcd(文字或变量, 行数, 列数)
```

`行数` 和 `列数` 都从 `0` 开始。文字会从你指定的位置开始显示：

```python
from easy_api import *

lcd(1)
guangmin(1)
clearlcd()

i = readguangmin()
showlcd("Light:", 0, 0)
showlcd(i, 0, 8)      # 从第 0 行第 8 列开始显示变量 i
showlcd("OK", 2, 5)
```

串口读写前，先决定使用哪个 UART 和波特率：

```python
setuart(2, 115200)
senduart(b"hello")
data = readuart()       # 立即读取当前已有数据
data = waituart(5000)   # 最多等待 5 秒
```

如果题目要求持续刷新，不要在 `easy_api.py` 里新增轮询函数，直接改 `starter/main.py`：

```python
from easy_api import *

def main():
    init()
    lcd(1)
    guangmin(1)

    while True:
        i = readguangmin()
        clearlcd()
        showlcd("Light:", 0, 0)
        showlcd(i, 0, 8)
        delay(1000)

main()
```
